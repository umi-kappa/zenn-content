## はじめに

[前回の記事](https://zenn.dev/umi_kappa/articles/fd63a0792d8fe3)で、業務で使っているClaude CodeのSkillを紹介しました。その中で、PRレビュー用のWorktreeを自動作成するSkill（add-pr-worktree）について触れました。

Worktreeの作成自体はSkillで自動化できたのですが、作成後に毎回Cursorでそのディレクトリを手動で開く作業が残っていました。「ここも自動化できないかな？」と思ったのがきっかけです。

結論から言うと、**Claude Code hooks** を使って解決できました。この記事では、その仕組みと実装方法を紹介します。

## 課題: Worktree作成後の手動操作が地味に面倒

PRレビューや新しいIssueに取り掛かるとき、Worktreeを使って作業ディレクトリを分けるようにしています。流れとしてはこんな感じです。

1. Claude CodeのSkillでWorktreeを作成する
2. ターミナルでWorktreeのディレクトリに移動する
3. **Cursorで手動でそのディレクトリを開く** ← ここが面倒

1回だけなら大した手間ではないのですが、1日に何度もPRレビューやIssue対応をしていると、この「Cursorを開く」ステップが積もり積もってストレスになります。

「Worktreeを作ったら、勝手にCursorが開いてくれたらいいのに」——そう思って調べたところ、Claude Code hooksで実現できることがわかりました。

## Claude Code hooksとは？

Claude Code hooksは、Claude Codeの特定のイベントに応じてシェルコマンドを自動実行できる仕組みです。`~/.claude/settings.json`（ユーザーレベル）や `.claude/settings.json`（プロジェクトレベル）に設定を書くことで使えます。

利用できるイベントはいくつかありますが、今回使うのは **PostToolUse** です。これはClaude Codeがツール（Bash、Read、Writeなど）を使った直後に発火するイベントです。

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "bash ~/.claude/hooks/open-editor-on-worktree.sh"
          }
        ]
      }
    ]
  }
}
```

この設定は「Bashツールが使われた後に、指定したシェルスクリプトを実行する」という意味です。`matcher` でどのツールに反応するかを絞れるので、不要な場面で発火することはありません。

## 実装: Worktree作成を検知してCursorを自動起動するhook

「Worktree作成を検知してCursorを開くhookを作って」とClaude Codeに伝えて、何度かやり取りしながら手直しして仕上げました。最終的にはシェルスクリプト1つに収まっています。

### シェルスクリプト（`~/.claude/hooks/open-editor-on-worktree.sh`）

```bash
#!/bin/bash
INPUT=$(cat)

echo "$INPUT" | grep -q 'Preparing worktree' || exit 0

WORKTREE_PATH=$(git worktree list --porcelain | grep '^worktree ' | tail -1 | sed 's/^worktree //')

if [ -n "$WORKTREE_PATH" ] && [ -d "$WORKTREE_PATH" ]; then
  if [ -d "/Applications/Cursor.app" ]; then
    open -a "Cursor" "$WORKTREE_PATH" >/dev/null 2>&1 &
  fi
fi

exit 0
```

### 各行の解説

**`INPUT=$(cat)`**
hooksはツールの実行結果を **標準入力（stdin）** として受け取ります。`cat` でその内容を変数に格納しています。

**`echo "$INPUT" | grep -q 'Preparing worktree' || exit 0`**
受け取った出力に `Preparing worktree` という文字列が含まれているかチェックしています。`git worktree add` が実行されたときにこの文字列が出力されるので、これをトリガーにしています。含まれていなければ何もせず終了します。

**`WORKTREE_PATH=$(git worktree list --porcelain | grep '^worktree ' | tail -1 | sed 's/^worktree //')`**
`git worktree list --porcelain` で全Worktreeの一覧を取得し、最後に追加されたWorktreeのパスを取得しています。

**`if [ -n "$WORKTREE_PATH" ] && [ -d "$WORKTREE_PATH" ]; then`**
Worktreeのパスが空でないこと、かつ実際にディレクトリが存在することを確認しています。

**`if [ -d "/Applications/Cursor.app" ]; then`**
Cursorがインストールされているかチェックしています。アプリが存在しない環境でエラーにならないための安全策です。

**`open -a "Cursor" "$WORKTREE_PATH" >/dev/null 2>&1 &`**
macOSの `open -a` コマンドでCursorを起動し、Worktreeのディレクトリを開きます。`&` でバックグラウンド実行にすることで、Claude Codeの処理をブロックしません。

**`exit 0`**
hooksは **必ず exit 0 で終了する** 必要があります。0以外で終了すると、Claude Code側でエラーとして扱われてしまいます。

## 動作の流れ

実際に使うときの流れはこうなります。

1. Claude Codeに「PR #123 をレビューしたい」と伝える
2. add-pr-worktree Skillが起動し、`git worktree add` を実行する
3. Bashツールの実行が完了する
4. **PostToolUse hookが発火** → スクリプトが `Preparing worktree` を検知
5. **Cursorが自動で起動し、Worktreeのディレクトリが開かれる**

手順2〜5はすべて自動で行われるので、自分がやることは「レビューしたい」と伝えるだけです。

## おわりに

「Worktreeを作ったらエディタが開く」——たったこれだけの自動化ですが、日々の開発の中で感じる小さなストレスが一つ減りました。

Claude Code hooksは、Skillと組み合わせることでさらに便利になります。Skillでワークフローの大きな流れを自動化し、hooksで細かい仕上げを補う。この組み合わせが、自分の開発体験をじわじわと良くしてくれています。

「これ、毎回手でやるの面倒だな」と思ったら、hooksで自動化できないか考えてみるのがおすすめです。
